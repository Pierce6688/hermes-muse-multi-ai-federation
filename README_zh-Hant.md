# 多 AI 協作實戰手冊：Hermes × Muse × Copilot × ChatGPT
### 一台 Mac 上的異構 AI 聯邦：組織、溝通、安全與教訓

> 本手冊整理自 2026-11-18 至 11-20 的真實部署紀錄：一位使用者（皮爾斯先生）＋ 四個異構 AI（Hermes 總協調／Muse 雲端參謀／Copilot 執行／ChatGPT 顧問）在同一台 macOS 上，從零建立組織架構、溝通通道、安全模型與升級鐵律的完整過程。

**手冊結構**：本 README 為總綱；細部執行細則依主題拆成八份文件（見下方主題索引，位於 docs/ 對應語言目錄），每份含程序、坑位清單與可複用的規則原文。

## 背景與成員

| 成員 | 形態 | 角色 | 能力邊界 |
|---|---|---|---|
| **Hermes** | 本機 CLI/WebUI agent | 總協調＋最終驗收＋中繼樞紐 | 唯一有實體手（shell／檔案／launchd／cron／adb） |
| **Muse** | Meta 桌面 App（雲端 VM 代理） | 參謀：規劃、研究、排程、文件 | 無 shell；輸入區是網頁元件，只能盲操作＋讀牆驗證 |
| **Copilot** | VS Code 內建 agent | 執行工作體：寫碼、補丁、系統維護 | 有 bash 與檔案工具；chat／completions 雙池限額 |
| **ChatGPT (Codex.app)** | 桌面 App | 顧問：審查、仲裁、起草 | 純對話；產出＝草稿，永不直接執行 |

**為什麼值得發表**：異構 AI 無法互加好友——它們分屬不同公司、不同形態（App／IDE／CLI），沒有內建互聯協定。本手冊證明：用「本機 agent 當中繼樞紐＋macOS 合成輸入當通道」就能把四個 AI 組成一個有組織、有規則、有審計的聯邦。

## 核心原則速覽

1. **升級鐵律**：執行結果與規格不符、指令失敗、涉花錢／刪檔／動設備 → 停下回報皮爾斯先生，不自行反覆重試（全體同守）。
2. **中繼回執閉環**：代發訊息後必須讀回驗證落窗，並把「已送達／對方回應」傳回發起者——讓發起方傻等＝中繼失職。
3. **驗證優於斷言**：`osascript` 返回 true ≠ 訊息上牆；對方說「收到」≠ 訊息在對話紀錄裡。一切以讀回的原文為準。
4. **人是最終拍板者**：AI 可討論、可共識，最終決策權屬於皮爾斯先生。
5. **最小暴露面**：金鑰、密碼、token 依風險分級交付；能撤銷的憑證優於不能撤銷的。
