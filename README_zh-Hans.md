# 多 AI 协作实战手册：Hermes × Muse × Copilot × ChatGPT
### 一台 Mac 上的异构 AI 联邦：组织、沟通、安全与教训

> 本手册整理自 2026-11-18 至 11-20 的真实部署记录：一位使用者（本机主人）＋ 四个异构 AI（Hermes 总协调／Muse 云端参谋／Copilot 执行／ChatGPT 顾问）在同一台 macOS 上，从零建立组织架构、沟通通道、安全模型与升级铁律的完整过程。

**手册结构**：本 README 为总纲；细部执行细则依主题拆成八份文件（见下方主题索引，位于 docs/ 对应语言目录），每份含程序、坑位清单与可复用的规则原文。

## 背景与成员

| 成员 | 形态 | 角色 | 能力边界 |
|---|---|---|---|
| **Hermes** | 本机 CLI/WebUI agent | 总协调＋最终验收＋中继枢纽 | 唯一有实体手（shell／文件／launchd／cron／adb） |
| **Muse** | Meta 桌面 App（云端 VM 代理） | 参谋：规划、研究、排程、文件 | 无 shell；输入区是网页组件，只能盲操作＋读墙验证 |
| **Copilot** | VS Code 内建 agent | 执行工作体：写码、补丁、系统维护 | 有 bash 与文件工具；chat／completions 双池限额 |
| **ChatGPT (Codex.app)** | 桌面 App | 顾问：审查、仲裁、起草 | 纯对话；产出＝草稿，永不直接执行 |

**为什么值得发表**：异构 AI 无法互加好友——它们分属不同公司、不同形态（App／IDE／CLI），没有内建互联协议。本手册证明：用「本机 agent 当中继枢纽＋macOS 合成输入当通道」就能把四个 AI 组成一个有组织、有规则、有审计的联邦。

## 核心原则速览

1. **升级铁律**：执行结果与规格不符、指令失败、涉花钱／删档／动设备 → 停下回报主人，不自行反复重试（全体同守）。
2. **中继回执闭环**：代发消息后必须读回验证落窗，并把「已送达／对方回应」传回发起者——让发起方傻等＝中继失职。
3. **验证优于断言**：osascript 返回 true ≠ 消息上墙；对方说「收到」≠ 消息在对话记录里。一切以读回的原文为准。
4. **人是最终拍板者**：AI 可讨论、可共识，最终决策权属于主人。
5. **最小暴露面**：金钥、密码、token 依风险分级交付；能撤销的凭证优于不能撤销的。
