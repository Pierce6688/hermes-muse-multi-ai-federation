# 主題 5：安全模型——金鑰與憑證（細節從簡）

> 依主人指示，本主題僅概述原則，不展開技術細節。

## 原則

1. **最小暴露面**：金鑰、密碼、token 經手的人越少越好。密碼類一律主人親手輸入，代理（AI）不經手明文。
2. **分級交付**：
   - 主密碼／長效憑證 → 只留在「主人＋本機管理者（Hermes）」體系，用於防禦 tailnet 其他節點。
   - 對外协作者 → 給**短效、可撤銷、白名單限定**的憑證（如 7 天期 scoped token），永不給主密碼。
3. **能力 ≠ 授權**：一個 agent「持有能力」不等於「被授權使用」。真實案例：向某 AI 交付 RSA 加密主密碼時，其 VM 安全機制直接攔截解密——事後共識：正確做法是最小權限憑證，而非靠承諾自律。
4. **可撤銷優先**：能即時撤銷的憑證，優於不能撤銷的。token 到期前走「主動輪換＋主人批准」流程。
5. **流程鐵律**：涉安全架構變更，方案先上牆給全體协作者過目、達成共識後才動工。

## 金鑰管理 SOP（示意，細節從簡）

```
① 主人在自己的終端機親自執行憑證新增指令
   （用工具內建的安全隱藏輸入提示貼上金鑰——不進指令列歷史，代理不經手明文）
② 本機管理者（Hermes）讀回憑證清單驗證：池內筆數、標籤、優先級
③ 到期清單檔案登記（標籤＋到期日），納入每日到期提醒
④ 驗證輪換：小額度實測，確認備援金鑰可被自動切換
⑤ 不派其他 AI 代執行——避免為此打開自動核准窗口，徒增風險面
```

## 成果

- 憑證分級制度落地：主密碼（Hermes/主人體系）、scoped token（對外协作者、可撤銷）、API key 池（同 provider 多把互為備援）。
- 到期主動告警：每日清單驅動的到期提醒（剩 10/7/3/1/0 天），到期前完成輪換，不斷線。
