# 主題 8：未來編制——Hermes 子 agent 四席草案（比照 v2 模式）

## 可行性基礎（CLI 實查）

- **Profiles**：`hermes profile create` 建立完全獨立實例（隔離 config／技能／記憶／會話）；profile 的 description 欄位就是給調度器認人用的。
- **Kanban 派工**：SQLite 持久化（崩潰不丟任務）、卡片依賴閘門（上遊完成才解鎖下遊）、dashboard 可視、卡住可 block 等人裁示。
- **delegate_task**：輕量會話內子任務，併發上限、深度限 1（子 agent 不能再生孫 agent，防失控）。
- 成本：profile 平時零成本（有卡才 spawn）；預設同款模型，可按卡換模型。

## 四席編制草案

| Profile | 角色 | 職責 | 邊界（不做） | 觸發 |
|---|---|---|---|---|
| `relay-hub` | 中繼樞紐 | 代發訊息給 Copilot／ChatGPT／Muse、讀回驗證落窗、回執閉環回報發起者 | 只中繼不執行業務、不動設定、不燒額度 | kanban 卡／cron 回執巡檢 |
| `verify-keeper` | 驗收官 | 實機驗收一切產出：檔案存在性／內容比對／命令實跑／讀回驗證，出驗收報告 | 只驗不改、不產出內容 | kanban 卡（掛產出任務下遊） |
| `archivist` | 檔案官 | 專案歸檔（YYYY_MM_DD 目錄）、INDEX 維護、Finder 自動開窗、交付清單 | 不刪檔、不改內容 | kanban 卡／cron |
| `watch-officer` | 值夜官 | cron 巡檢：看門狗狀態、耗電審計、API key 到期、夜間制度、token 續期提醒 | 只報告不動手 | cron 定時 |

## 共同鐵律（寫進每個 profile）

1. 升級鐵律：花錢／刪檔／動設備 → 停手回報主人。
2. 回執閉環：完成 → 系統通知＋報告本體寫在主會話。
3. 繁中回報；重大分叉先問主人。

## 專案編制（重大專案與外部 AI 協作時）

- 上場三席：relay-hub（對外訊息）、verify-keeper（外部產出實機驗收）、archivist（定案留存落檔）。
- watch-officer 不進專案編制，但長任務過夜時背景盯進度。
- 流水線：起草 → 成品化 → 實機驗收 → 歸檔（見主題 1）。

## 分階段上線

1. 主人拍板名單 → 2. 建 profile（含 description＋預裝對應技能）→ 3. 試運轉一張低風險卡驗全鏈路 → 4. 常態化 cron。

## 泛化規則

1. 子 agent 的價值在「職責隔離」：中繼的不驗收、驗收的不歸檔，避免單點自審。
2. 編制按需生長：先四席，遇到新工種再加席，不預先膨脹。
3. 每席上線前必須通過一張試運轉卡的全鏈路驗證，不通不上崗。
