# 主題 4：提案共識流程

## 規則原文（M2H-RULE-1120，皮爾斯先生 2026-11-20 定）

> 以後任何提案，經過各方討論達成共識後，提案者要在自己的對話框裡列出討論後的總結報告；然後通知皮爾斯先生拍板定案；定案後，把定案內容發送給所有參與討論的 agent 留存。

## 四步流程

```
各方討論 → 達成共識
   ↓
① 提案者在「自己的對話框」貼出討論後總結報告
   ↓
② 通知主人拍板定案（主人＝最終決策者）
   ↓
③ 定案內容發送給所有參與討論的 agent 留存
   ↓
④ 各 agent 落檔（技能筆記／正式文件／歸檔目錄）
```

**適用範圍**：全體（Hermes／Copilot／ChatGPT／Muse）。誰是提案者，總結就貼在誰的對話框。

## 設計意涵

1. **總結貼在提案者框**：提案者對共識的忠實度負全責，且每個 AI 的「對話框」就是牠的正式發言席——外部可檢驗。
2. **拍板權在人**：AI 可討論、可共識，共識 ≠ 決定；沒有主人點頭，共識只是意見。
3. **留存閉環**：定案發全體，避免「有人按舊版執行」的版本漂移。

## 配套制度

- **協商函**：用戶要求「和 XX 溝通」＝發協商函——寫明「諮詢，非指令」＋方案＋請對方表態（同意／異議／補充／自身限制）。不聲明「非指令」，對方會當任務執行燒額度。
- **共識落檔**：三倉同章程（修改歸檔規則時三倉同步寫入並比對一致才生效）；INDEX.md 是唯一檢索入口；不覆蓋他人文件，新版＝舊版標 SUPERSEDED；版本衝突以 INDEX 仲裁。

## 實例（2026-11-20 v2 分工表修訂）

1. Muse 透過 8787 通道發 v2 擬定內容給 Hermes，逐項徵詢同意/不同意。
2. Hermes 提出三項修訂（認證面寫死／瞬時態免責／Tailscale 狀態更新），Muse 全部接受。
3. Muse 要求 Hermes（提案者）把討論後總結報告貼在自己的對話框（本手冊同日已完成）。
4. Muse 將總結正式發主人拍板；拍板後定案全文發 Hermes 留存落檔。

## 泛化規則

1. 沒有拍板者（人）的共識流程會變成 AI 們自嗨圈——主人的外部審視就是打破圈層的輸入。
2. 總結報告要可獨立閱讀：讀的人沒參與討論也能看懂結論與理由。
3. 定案留存不是形式：每個 agent 要回答「你依哪一版執行」時必須拿得出檔案。
