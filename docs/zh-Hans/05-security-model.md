# 主题 5：安全模型——金钥与凭证（细节从简）

> 依主人指示，本主题仅概述原则，不展开技术细节。

## 原则

1. **最小暴露面**：金钥、密码、token 经手的人越少越好。密码类一律主人亲手输入，代理（AI）不经手明文。
2. **分级交付**：
   - 主密码／长效凭证 → 只留在「主人＋本机管理者（Hermes）」体系，用于防御 tailnet 其他节点。
   - 对外协作者 → 给**短效、可撤销、白名单限定**的凭证（如 7 天期 scoped token），永不给主密码。
3. **能力 ≠ 授权**：一个 agent「持有能力」不等于「被授权使用」。真实案例：向某 AI 交付 RSA 加密主密码时，其 VM 安全机制直接拦截解密——事后共识：正确做法是最小权限凭证，而非靠承诺自律。
4. **可撤销优先**：能即时撤销的凭证，优于不能撤销的。token 到期前走「主动轮换＋主人批准」流程。
5. **流程铁律**：涉安全架构变更，方案先上墙给全体协作者过目、达成共识后才动工。

## 金钥管理 SOP（示意，细节从简）

```
① 主人在自己的终端机亲自执行凭证新增指令
   （用工具内建的安全隐藏输入提示贴上金钥——不进指令列历史，代理不经手明文）
② 本机管理者（Hermes）读回凭证清单验证：池内笔数、标签、优先级
③ 到期清单文件登记（标签＋到期日），纳入每日到期提醒
④ 验证轮换：小额度实测，确认备援金钥可被自动切换
⑤ 不派其他 AI 代执行——避免为此打开自动核准窗口，徒增风险面
```

## 成果

- 凭证分级制度落地：主密码（Hermes/主人体系）、scoped token（对外协作者、可撤销）、API key 池（同 provider 多把互为备援）。
- 到期主动告警：每日清单驱动的到期提醒（剩 10/7/3/1/0 天），到期前完成轮换，不断线。
