# 主题 8：未来编制——Hermes 子 agent 四席草案（比照 v2 模式）

## 可行性基础（CLI 实查）

- **Profiles**：`hermes profile create` 建立完全独立实例（隔离 config／技能／记忆／会话）；profile 的 description 栏位就是给调度器认人用的。
- **Kanban 派工**：SQLite 持久化（崩溃不丢任务）、卡片依赖闸门（上游完成才解锁下游）、dashboard 可视、卡住可 block 等人裁示。
- **delegate_task**：轻量会话内子任务，并发上限、深度限 1（子 agent 不能再生孙 agent，防失控）。
- 成本：profile 平时零成本（有卡才 spawn）；预设同款模型，可按卡换模型。

## 四席编制草案

| Profile | 角色 | 职责 | 边界（不做） | 触发 |
|---|---|---|---|---|
| `relay-hub` | 中继枢纽 | 代发消息给 Copilot／ChatGPT／Muse、读回验证落窗、回执闭环回报发起者 | 只中继不执行业务、不动设定、不烧额度 | kanban 卡／cron 回执巡检 |
| `verify-keeper` | 验收官 | 实机验收一切产出：文件存在性／内容比对／命令实跑／读回验证，出验收报告 | 只验不改、不产出内容 | kanban 卡（挂产出任务下游） |
| `archivist` | 档案官 | 专案归档（YYYY_MM_DD 目录）、INDEX 维护、Finder 自动开窗、交付清单 | 不删档、不改内容 | kanban 卡／cron |
| `watch-officer` | 值夜官 | cron 巡检：看门狗状态、耗电审计、API key 到期、夜间制度、token 续期提醒 | 只报告不动手 | cron 定时 |

## 共同铁律（写进每个 profile）

1. 升级铁律：花钱／删档／动设备 → 停手回报主人。
2. 回执闭环：完成 → 系统通知＋报告本体写在主会话。
3. 繁中回报；重大分叉先问主人。

## 专案编制（重大专案与外部 AI 协作时）

- 上场三席：relay-hub（对外消息）、verify-keeper（外部产出实机验收）、archivist（定案留存落档）。
- watch-officer 不进专案编制，但长任务过夜时背景盯进度。
- 流水线：起草 → 成品化 → 实机验收 → 归档（见主题 1）。

## 分阶段上线

1. 主人拍板名单 → 2. 建 profile（含 description＋预装对应技能）→ 3. 试运转一张低风险卡验全链路 → 4. 常态化 cron。

## 泛化规则

1. 子 agent 的价值在「职责隔离」：中继的不验收、验收的不归档，避免单点自审。
2. 编制按需生长：先四席，遇到新工种再加席，不预先膨胀。
3. 每席上线前必须通过一张试运转卡的全链路验证，不通不上岗。
