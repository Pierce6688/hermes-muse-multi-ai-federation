# 主题 4：提案共识流程

## 规则原文（M2H-RULE-1120，皮尔斯先生 2026-11-20 定）

> 以后任何提案，经过各方讨论达成共识后，提案者要在自己的对话框里列出讨论后的总结报告；然后通知皮尔斯先生拍板定案；定案后，把定案内容发送给所有参与讨论的 agent 留存。

## 四步流程

```
各方讨论 → 达成共识
   ↓
① 提案者在「自己的对话框」贴出讨论后总结报告
   ↓
② 通知主人拍板定案（主人＝最终决策者）
   ↓
③ 定案内容发送给所有参与讨论的 agent 留存
   ↓
④ 各 agent 落档（技能笔记／正式文件／归档目录）
```

**适用范围**：全体（Hermes／Copilot／ChatGPT／Muse）。谁是提案者，总结就贴在谁的对话框。

## 设计意涵

1. **总结贴在提案者框**：提案者对共识的忠实度负全责，且每个 AI 的「对话框」就是它的正式发言席——外部可检验。
2. **拍板权在人**：AI 可讨论、可共识，共识 ≠ 决定；没有主人点头，共识只是意见。
3. **留存闭环**：定案发全体，避免「有人按旧版执行」的版本漂移。

## 配套制度

- **协商函**：用户要求「和 XX 沟通」＝发协商函——写明「咨询，非指令」＋方案＋请对方表态（同意／异议／补充／自身限制）。不声明「非指令」，对方会当任务执行烧额度。
- **共识落档**：三仓同章程（修改归档规则时三仓同步写入并比对一致才生效）；INDEX.md 是唯一检索入口；不覆盖他人文件，新版＝旧版标 SUPERSEDED；版本冲突以 INDEX 仲裁。

## 实例（2026-11-20 v2 分工表修订）

1. Muse 透过 8787 通道发 v2 拟定内容给 Hermes，逐项征询同意/不同意。
2. Hermes 提出三项修订（认证面写死／瞬时态免责／Tailscale 状态更新），Muse 全部接受。
3. Muse 要求 Hermes（提案者）把讨论后总结报告贴在自己的对话框（本手册同日已完成）。
4. Muse 将总结正式发主人拍板；拍板后定案全文发 Hermes 留存落档。

## 泛化规则

1. 没有拍板者（人）的共识流程会变成 AI 们自嗨圈——主人的外部审视就是打破圈层的输入。
2. 总结报告要可独立阅读：读的人没参与讨论也能看懂结论与理由。
3. 定案留存不是形式：每个 agent 要回答「你依哪一版执行」时必须拿得出文件。
